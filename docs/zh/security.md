# 安全

## 认证与授权

### 用户

用户由 GitLab 数字用户 ID 标识——改用户名不影响任何东西。GitLab 只用于获取身份，服务端不查询群组，也不保存 GitLab access token。

访问控制在本地管理：管理员在数据库里维护用户白名单。未批准的用户可以完成 OAuth 登录，但只能看到自己的状态或退出。所有 API 调用和部署提交都检查本地用户状态——没有缓存，也不会回调 GitLab。

配置文件中的初始管理员不能从管理面板禁用。撤销用户会立即使其会话和所有 API Key 失效，但不会自动下线其团队的 CI 信任或公开站点。

### 浏览器会话

- 所有写操作验证 `Origin` 头。
- Cookie 使用 `__Host-` 前缀、`Secure`、`HttpOnly`、`SameSite=Lax`。
- Bearer token 走独立的认证路径——不接受 query string 凭据。

### API Key

- Key 明文只在创建时显示一次，服务端只存 SHA-256 哈希。
- Key 有过期时间（默认 90 天，最长 365 天）。
- Key 不能授予超出用户角色的权限。

### OIDC（CI Token）

- 只接受已配置 issuer 的 HTTPS JWKS 端点。忽略 JWT 自带的 `jku` 等外部取钥建议。
- 算法限定 RS256，校验 issuer、audience 和有效期。
- 每次 token 交换都获取 JWKS，密钥轮换立即生效。JWKS 端点故障时拒绝 token（不放行）。
- MR 流水线发布由每条信任规则的 `allow_mr_pipelines` 控制（默认关闭）。来源和执行仓库必须一致——跨 fork 的 MR 始终拒绝。
- 每条信任规则可以要求 `ref_protected`。开启后只接受布尔 `true` 或字符串 `"true"`，缺失或其他值拒绝。
- Token 交换产生最长 5 分钟的短期凭据。幂等交换所需的临时明文存储在受限数据库表中，过期后清理。

## ZIP 上传校验

上传的 ZIP 在**沙箱子进程**中校验和解压，有严格的资源限制。

### 拒绝的内容

服务端会拒绝包含以下内容的 ZIP：

- 绝对路径、`..` 遍历、或解析后越出归档根目录的路径
- 反斜杠、Windows 盘符
- 重复或冲突的路径（同一名称既是文件又是目录）
- 无效 UTF-8、控制字符
- 路径超过 1024 字节或目录深度超过 32 层
- 符号链接、设备文件或其他非常规条目

### 结构检查

解压前，服务端会验证中央目录、EOCD、本地头、文件名、压缩算法、flags、偏移量和条目重叠区间。只接受从偏移 0 开始、条目之间没有间隙的单卷 ZIP，不支持 ZIP64。

每个文件都读到 EOF，校验 CRC 和实际长度。大小限制分别对元数据声明和实际解压输出独立执行——不依赖 ZIP 声明的大小。

只有目录没有常规文件的归档在校验完成后被拒绝。零字节常规文件是允许的。

### 资源限制

| 限制项 | 默认值 |
|--------|--------|
| 请求体 | 128 MiB |
| 解压总量 | 100 MiB |
| 最大条目数 | 10,000 |
| 最大路径长度 | 1,024 字节 |
| 最大目录深度 | 32 层 |
| 上传超时 | 120 秒 |
| 子进程地址空间 | 2 GiB |

子进程还有 CPU、文件描述符和单文件大小限制。Go 内存限制设为地址空间的一半。

上传并发：全局 4 个、每用户 1 个（同一用户的所有 Key 和会话共享额度）。OIDC 额度按 issuer + GitLab 项目 ID 分配——换 token 或信任规则不能绕过。

> 提高上传大小限制时，记得同步调整请求体限制、磁盘配额、systemd 单元内存和 worker 限额。

### 失败隔离

格式错误的上传只影响私有 staging 任务——不会触及已发布的内容。超时、取消和失败都会清理 staging 目录。孤立的 release 文件在宽限期后回收。

权限和配额在接收和提交两个阶段分别检查。

## 静态内容

用户可以上传浏览器可执行的 JavaScript，但服务端**绝不执行上传的内容**。没有动态处理器——只有静态文件服务。

平台生成的符号链接只指向受管理的 release 目录。归档文件不能生成符号链接。

### 共享 Origin 注意事项

所有内容站点共享同一个 origin。不要依赖路径来做安全隔离——在内容 origin 下，不要使用管理会话、敏感的跨站 Cookie 或基于 URL 路径的租户边界。

服务端不保证用户上传内容的可信性。保持静态服务器更新。

### 管理界面隔离

管理界面部署在反代后面的独立静态目录中，没有打包进 Go 二进制或后端容器。示例反代配置在管理响应上设置了 CSP、`X-Content-Type-Options: nosniff`、`Referrer-Policy` 和 `must-revalidate` 缓存。

## 备份

备份文件（权限 0600）包含授权数据、Key 哈希和短期 OIDC 凭据。只从可信来源恢复。

备份恢复使用专用的受限 tar 读取器——不复用 ZIP 上传校验器。
